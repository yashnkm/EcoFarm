🚜 EcoFarm SCADA Platform

IoT/SCADA Platform for Industrial Monitoring and Control

Java 21 Spring Boot 4 React 19 TypeScript PostgreSQL MQTT WebSocket

📋 Project Overview

Project Type

Full-stack web application for Industrial IoT (IIoT) monitoring and control platform

Purpose

EcoFarm is a comprehensive SCADA (Supervisory Control and Data Acquisition) platform designed to:

  • Monitor IoT devices and sensors in real-time
  • Collect and store time-series data (readings)
  • Control industrial equipment through gateways
  • Manage multi-tenant environments with role-based access
  • Generate alerts and rules for anomaly detection
  • Provide a user-friendly dashboard for visualization

Target Users

  • Industrial facility managers
  • IoT system administrators
  • Equipment operators
  • System integrators

🔐 Authentication & Authorization

Authentication Flow

User Login (LoginPage) ↓ POST /api/v1/auth/login ├─ Credentials validation ├─ JWT token generation └─ Refresh token issued ↓ Store in Zustand (authStore) ├─ Access Token (15 min expiry) ├─ Refresh Token (7 days) └─ User Profile ↓ Include JWT in Authorization header ↓ Interceptor on 401 → Refresh token

Role-Based Access Control

Role Responsibilities Permissions
SUPER_ADMIN System administrator ✅ All operations, tenant management, broker config
TENANT_ADMIN Organization admin ✅ Manage tenant resources, users, devices, gateways
OPERATOR Equipment operator ✅ View data, control devices, acknowledge alerts
VIEWER Read-only access ✅ View dashboards & data only

Protected Routes (Frontend)

  • ProtectedRoute component checks authentication
  • Redirects to login if no valid token
  • Validates role-based access to pages
  • Handles token refresh automatically

🔄 Development Workflow

Code Organization Best Practices

  • Controllers → Handle HTTP requests, validate input, delegate to services
  • Services → Contain business logic, orchestrate repositories
  • Repositories → Spring Data JPA interfaces for database access
  • Mappers → MapStruct for entity ↔ DTO conversion
  • DTOs → Request/Response objects for API contracts
  • Entities → JPA domain models with relationships
  • Enums → Type-safe constants for status, protocols, etc.

Frontend Code Organization

  • Pages → Full page components (routes)
  • Components → Reusable UI components (buttons, cards, dialogs)
  • Hooks → Custom React hooks (useLiveReadings, use-mobile)
  • API Modules → Organized API client methods by resource
  • Store → Zustand global state (auth)
  • Types → TypeScript interfaces & types
  • Lib → Utilities & helpers

Common Workflows

Task Steps
Add New API Endpoint 1. Create DTO (request/response) 2. Create Entity 3. Add Repository 4. Create Service 5. Add Controller with @PreAuthorize
Add New Page 1. Create page component 2. Add API client method 3. Use TanStack Query hook 4. Add route in App.tsx 5. Add sidebar link
Connect Real-Time Data 1. Use useLiveReadings hook 2. Subscribe to WebSocket topic 3. Update component on message 4. Unsubscribe on unmount
Add Validation 1. Backend: @Valid annotations + constraint annotations 2. Frontend: Zod schema 3. React Hook Form integration
Add Role-Based Access 1. Backend: @PreAuthorize("hasAnyRole('ROLE1', 'ROLE2')") 2. Frontend: Conditional rendering based on authStore.user.role

  • Java 21 JDK
  • PostgreSQL 12+
  • Node.js 18+ & npm
  • Maven (or use mvnw)
  • MQTT Broker (for full functionality)

# 1. Navigate to backend directory cd ecoFarm # 2. Configure database (application.properties) # Update spring.datasource.url, username, password # 3.   2. Login with test credentials (set up in database)
  3. Navigate to Dashboard
  4. Configure MQTT Broker (/admin/brokers)
  5. Create a Site
  6. Create a Gateway within the Site
  7. Add Devices to the Gateway
  8. View real-time readings on Dashboard

💡 Project Insights & Architecture Patterns

Design Patterns Used

MVC Pattern

Controller → Service → Repository → Database

Dependency Injection

Spring IoC container manages dependencies

Data Transfer Objects

Separate API contracts from database models

Event-Driven

MQTT & WebSocket for real-time updates

Repository Pattern

Spring Data JPA abstracts database queries

Observer Pattern

React Query & Zustand for state updates

Scalability Considerations

  • Multi-Tenancy: Isolated data per tenant for horizontal scaling
  • Connection Pooling: PostgreSQL with connection pooling for concurrent users
  • Caching: React Query caching reduces API calls
  • WebSocket: Efficient real-time updates vs polling
  • MQTT QoS: Configurable quality of service for message delivery
  • Database Indexing: Consider indexes on Tenant, Device, Readings tables
  • Microservices Ready: Service layer can be extracted to separate services

Security Best Practices Implemented

  • JWT with refresh token rotation
  • Role-based access control (RBAC)
  • Spring Security with PreAuthorize annotations
  • CORS configuration for frontend
  • Password hashing (Spring Security UserDetailsService)
  • Audit logging for user actions
  • Tenant data isolation
  • Input validation (Jakarta Bean Validation)
